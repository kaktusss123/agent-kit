# agent-kit

Личный набор инструкций и инструментов для инженерной работы с ИИ, прежде
всего в [Pi](https://www.npmjs.com/package/@earendil-works/pi-coding-agent)
(пакет `@earendil-works/pi-coding-agent`). Повторно использует навыки и правила
в разных проектах: помогает сначала уточнить задачу, затем реализовать её
в отдельном git worktree,
проверить результат и сделать локальный коммит.

Это не автономный агент и не самостоятельная среда выполнения. Pi, Claude Code
или Codex CLI устанавливаются отдельно и выполняют работу с выбранной моделью.

## Что входит

- Навыки в [`skills/`](skills/) для исследования кода, спецификаций,
  реализации, отладки и ревью. Общие [правила](rules/AGENTS.md) задают
  общение и дисциплину Git.
- Процесс `/spec` → `/dev`: от согласованной спецификации к реализации
  субагентами-владельцами репозиториев, с независимым ревью при необходимости.
- Управляемые git worktree и `agent-kit task` для изоляции изменений от
  основного checkout и коммитов с точным списком файлов и запуском Git hooks.
- Расширения Pi: субагенты с ролями моделей, вопросы пользователю, поиск
  в интернете, список задач и сведения о сессии.

По умолчанию агент отвечает по-русски. Язык и остальные договорённости можно
изменить в [`rules/AGENTS.md`](rules/AGENTS.md) своего клона.

## Быстрый старт

Нужны Node.js >= 24, `git` и установленная среда работы с агентом.
Установщику и `agent-kit task` не нужны `npm install`, сборка или Bun.

Для Pi выполните в терминале:

```sh
git clone https://github.com/kaktusss123/agent-kit.git ~/src/agent-kit
cd ~/src/agent-kit
./bin/agent-kit install pi
```

Добавьте `~/.local/bin` в `PATH`, если его там нет. Например, для текущей
POSIX-совместимой оболочки:

```sh
export PATH="$HOME/.local/bin:$PATH"
agent-kit status
```

Сохраните настройку `PATH` в конфигурации своей оболочки. Запустите новую
сессию Pi в репозитории проекта. Установщик создаёт симлинки на клон,
поэтому не удаляйте и не перемещайте `~/src/agent-kit` после установки.

Другие среды устанавливаются отдельно или добавляются к выбранным:

```sh
./bin/agent-kit install claude-code
./bin/agent-kit install codex
```

Pi получает весь набор расширений и промптов. Claude Code получает навыки,
правила, команды `/spec` и `/dev`, определения субагентов и плагин с hooks.
Codex получает навыки, объединённые правила, `$spec` / `$dev` и hooks,
но не расширения Pi. У всех трёх общее ядро `agent-kit task`; гарантии
делегирования различаются. См. [установку](docs/installation.md) и
[ограничения Codex](docs/codex.md).

В Codex явно проверьте и одобрите сторонние hooks через `/hooks`.
В Claude Code управляемые настройки `allowManagedHooksOnly` могут запретить
hooks плагина. Наличие файлов ещё не доказывает, что защита активна.

## Первая задача

Ниже сообщения агенту в Pi или Claude Code, а не команды оболочки.
Подставьте описание своей задачи:

```text
/spec Добавь проверку пустого имени пользователя. Работай без тикета.
```

Агент уточнит требования и подготовит `SPEC.md` в каталоге задачи, не меняя
продуктовый код. После согласования спецификации отправьте:

```text
/dev Реализуй согласованную спецификацию.
```

В Codex используйте `$spec` и `$dev` вместо `/spec` и `/dev`.
Реализация идёт в управляемом worktree, не в основном checkout. Владелец
проверяет закоммиченный результат; отправка в удалённый репозиторий требует
отдельного запроса. Подробнее о владельцах, ревью и инструментах Pi:
[рабочий процесс](docs/workflow.md).

Защитные проверки помогают не записать изменения не туда. Это не песочница
для произвольного кода. Отказ проверки означает, что нужно исправить маршрут
в worktree, а не повторить запись другим инструментом.

## Обновление и удаление

```sh
agent-kit install          # reconcile links for saved hosts
agent-kit update           # git pull --ff-only, then install
agent-kit uninstall pi     # remove owned Pi links
agent-kit uninstall        # remove all owned host links and clear selection
```

Свежий `install` без аргументов ставит все три среды. После выбора сред
`install` и `update` без аргументов используют сохранённый выбор.
Чужие файлы установщик не перезаписывает: конфликт ресурса среды возвращает
код 1. Занятый чужим файлом лаунчер является исключением: установщик лишь
предупреждает и пропускает его. Проверьте лаунчер через `agent-kit status`
или `./bin/agent-kit status`. Установка из другого клона перенаправит
собственные ссылки на него. [Корни и владение ссылками](docs/installation.md).
