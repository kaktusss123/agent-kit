# Границы Core и согласованная миграция

Это справочник миграции прежних установок с корпоративными ресурсами,
а не инструкция новой установки. Для нового клона используйте
[руководство по установке](installation.md). Описанный ниже порядок важен
для сохранения старых ссылок до обновления прежнего checkout.

`agent-kit` (Core) поставляет общие skills, правила, команды, расширения Pi и
`agent-kit task`. Он работает без ZAVOD, корпоративной поставки и корпоративной
сети. Публичное чтение состояния Core описано в
[read-only-state.md](read-only-state.md); Core не владеет транспортом или
подключением внешней инспекции.

ZAVOD поставляет и подключает собственную инспекцию к управляемым им процессам.
Отдельного продукта `agent-kit-inspection` нет. Корпоративные ресурсы и их
установка принадлежат отдельной поставке Cloudru, независимой от Core. Старый
`--profile full` отклоняется установщиком Core с кодом 2 и инструкцией
миграции до изменения ссылок, состояния или выполнения pull. Единственный
допустимый профиль — `core`; без флага устанавливается тот же набор.

Снимки Core остаются необязательным способом закрепить его расширения. Они не
поставляют инспекцию ZAVOD; опубликованные снимки старых версий не
переписываются. Удаление файлов из текущего дерева не очищает Git-историю.
Публикация и аудит истории требуют отдельных решений.

## Безопасное переключение

1. Подготовить и проверить согласованные кандидаты Core, ZAVOD и Cloudru,
   инвентаризировать ссылки и записи владения, сохранить проверенный комплект
   отката. Убедиться, что корпоративная поставка доступна и проверена; не
   удалять единственный доступный экземпляр переносимых ресурсов.
2. **До любого pull прежнего checkout Core, включая старый `agent-kit update`,
   выполнить и проверить передачу принадлежащих Core корпоративных ссылок и
   их владения в Cloudru.** Старый updater сначала делает `git pull --ff-only`,
   затем запускает установщик: отказ нового установщика после pull не сохранит
   старые цели ссылок, удалённые из дерева. При переносе исключить параллельные
   install/update/uninstall и ручные изменения тех же ссылок и записей.
   Владение подтверждается записью и точной целью symlink, не одним именем;
   чужие файлы и ссылки не присваиваются. При конфликте или прерывании
   остановиться и восстановить передачу согласно процедуре Cloudru.
3. Согласовать окно переключения и дождаться окончания активной работы либо
   получить отдельное разрешение на её остановку. Обновить код и конфигурацию
   согласованным комплектом, убрать старые явные пути инспекторов и устаревшие
   зависимости от обязательного обновления Core, не ослабляя пользовательскую
   изоляцию.
4. Запустить новые процессы и проверить независимую работу, ссылки и их
   владельцев, а также работу с Core и без него. Отсутствие источника Core не
   означает пустой результат или ошибку базовой сессии. Старые процессы не
   считаются мигрированными лишь потому, что ещё отвечают.
5. При откате вернуть согласованный комплект кода, конфигурации и владения,
   не смешивая произвольные версии. Историю сессий и опубликованные снимки не
   переписывать.

## Владение ссылками

Формат Core сохраняется: `$XDG_STATE_HOME/agent-kit/links.tsv` для Pi,
`links-claude-code.tsv` для Claude Code, строки `<dest-rel>\t<absolute-source>`.
Если `XDG_STATE_HOME` не задан, используется `~/.local/state`. Файлы `hosts`
и `command.tsv` сохраняют прежний смысл. Корпоративная поставка хранит своё
владение отдельно; Core его не читает и не запускает её установщик.

При reconcile старые inspection/work-ссылки удаляются только при наличии
записи Core и точном совпадении `readlink` с записанным источником. Изменённая
цель приводит к освобождению старой записи, а не удалению ссылки. Поэтому
переставленная Cloudru ссылка сохраняется даже при прерывании передачи до
очистки старой записи Core. Чужие ссылки и обычные файлы не трогаются.
`uninstall` также использует только свои записи и точную цель. Это не заменяет
журнал восстановления корпоративного установщика: передачу нужно завершить
до обновления Core, без параллельных изменений.

Core не редактирует пользовательские `settings.json` и команды запуска.
Старые явные `-e` пути инспекторов нужно убрать при согласованном переключении;
сохранённая пользователем чужая ссылка не превращается в ресурс Core.

Локальная готовность кода сама по себе не означает, что корпоративная поставка
опубликована или реальные установки переведены. Выполнение переключения и
публикация требуют отдельного операционного решения.
