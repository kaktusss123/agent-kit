# План разделения agent-kit на core / inspection / cloudru

Статус: план первой фазы (логическое разделение внутри текущего checkout).
Репозитории не создаются, ничего не публикуется, удалённые операции не
выполняются.

Основание — ограничения, которые уже действуют в коде и ADR:

- инспекция опциональна и инертна: без bridge-реестра провайдер ничего не
  регистрирует и не влияет на сессию
  ([`extensions/inspection-provider/README.md`](../extensions/inspection-provider/README.md));
- канал инспекции read-only, недолговечный и инертен без валидных наследуемых
  дескрипторов ([`docs/adr/adr-0006.md`](adr/adr-0006.md)), а ZIP-транспорт и
  wire принадлежат контроллеру
  ([`extensions/inspection-provider/README.md`](../extensions/inspection-provider/README.md));
- установка обслуживает несколько hosts и не обязана ставить всё сразу
  ([`docs/adr/adr-0007.md`](adr/adr-0007.md),
  [`docs/adr/adr-0009.md`](adr/adr-0009.md)), поэтому рабочие навыки вынесены в
  профиль `full` и не ставятся по умолчанию.

## 1. Целевые компоненты

| Компонент | Что входит | Зависимости |
| --- | --- | --- |
| `agent-kit-core` | `bin/` (установщик и CLI), `skills/*` кроме `WORK_SKILLS`, `extensions/*` (субагенты, task-workspace, терминальные расширения), `prompts/`, `rules/`, `claude-code/`, `tests/` | нет зависимости от ZAVOD |
| `agent-kit-inspection` | `extensions/inspection-provider/` (ZIP v1) и `extensions/inspection-channel/` (устаревший FD-канал, deprecated) | Core только через read-only seam; ZIP-транспорт принадлежит ZAVOD |
| `agent-kit-cloudru` | `skills/kuber-nagibator/` целиком (инструкции и рабочие скрипты скилла) | самостоятельная установка поверх Core, без зависимости от ZAVOD |

Граница «рабочих навыков» задана явным списком `WORK_SKILLS` в
`bin/lib/entities.mjs` — раскладка репозитория не отличает рабочий навык от
инженерного, поэтому список ручной и меняется только вместе с переносом
каталога. Первая фаза не выносит `skills/kuber-nagibator/` из репозитория: он
остаётся на месте и только исключается из установки по умолчанию.

## 2. Что уже сделано в этой фазе

- Профили установщика: `agent-kit install [--profile core|full]`, по умолчанию
  `core` (без рабочих навыков), `full` — включая их. Uninstall удаляет всё, что
  записано в ownership-таблице, независимо от профиля; `update` без флага
  сохраняет текущий набор ссылок; `status` показывает профиль каждого host'а.
- Обратная совместимость: установка без флага на машине, где рабочий навык уже
  стоит, его не удаляет — удаляет только `reconcile.mjs` и только ссылку,
  которую agent-kit сам создал (`readlink === recorded.src`).
- Snapshot не зависит от профиля: в снимок входит весь `extensions/` из
  `git ls-files --cached HEAD`, поэтому `extensions/inspection-provider/`
  попадает в снапшот без отдельного списка (`tests/snapshot/run.sh`, T25).
- Тесты профилей и обратной совместимости — `tests/installer/run.sh`, T43–T47.

Предпосылки выделения `agent-kit-inspection` уже выполнены в этой ветке:

- контракт провайдера и его гарантии (инертность, отсутствие регистраций
  инструментов/промптов/статусов, границы владения) —
  [`extensions/inspection-provider/README.md`](../extensions/inspection-provider/README.md);
- транспорт, направление канала и запрет зависимости от ZAVOD —
  [`docs/adr/adr-0006.md`](adr/adr-0006.md);
- версионированный read-only ABI Core —
  `extensions/subagents/inspection-seam.ts`;
- интеграционные тесты провайдера, включая отдельные jiti-графы
  (`extensions/inspection-provider/index.test.ts`, `identity.test.ts`,
  `cross-graph.test.ts`);
- вхождение провайдера в схему-2 снапшот — `tests/snapshot/run.sh`, T25.

## 3. Порядок миграции

Шаги выполняются по одному; каждый следующий начинается только после того, как
предыдущий проверен на временных `HOME`/`PI_AGENT_DIR`/`CLAUDE_CONFIG_DIR`.

1. **Инвентаризация владельцев.** Для каждой целевой ссылки Pi и Claude, для
   `~/.local/state/agent-kit/{links*.tsv,hosts,command.tsv}` и лаунчера
   `~/.local/bin/agent-kit` установить, кто ею владеет. Глобального удаления
   нет: источник истины — ownership-запись, а не прежняя версия установщика.
2. **Новая установка на временных корнях.** Профили, hosts и конфликты
   проверяются в песочнице (`tests/installer/run.sh`); на реальных корнях —
   только после зелёного прогона.
3. **Передача ownership.** Старый установщик удаляет или перенаправляет
   **только** ссылки, которые сам создал; чужие файлы и ручные симлинки
   остаются нетронутыми и репортятся как conflict (это уже поведение
   `bin/lib/reconcile.mjs`). Выделение компонента в отдельный репозиторий не
   даёт ему права удалять ссылки прежнего репозитория: принимающая сторона
   должна либо унаследовать запись, либо оставить ссылку как чужую.
4. **Имена команд и ссылок.** `agent-kit task` не переименовывается: его
   вызывают Claude adapter ZAVOD и skills (`docs/adr/adr-0012.md`), поэтому
   имя CLI, лаунчер и путь к `extensions/task-workspace/cli.ts` сохраняются.
   Любое переименование требует релиза-обёртки в Core, который остаётся
   работоспособным после обновления ZAVOD.
5. **Release pinning.** `agent-kit snapshot <releases-dir>` остаётся за Core:
   формат `<releases>/<sha>/{extensions,node_modules,manifest.json}` + `current`,
   схема 2, `.lock`. Снапшот обязан содержать провайдера инспекции, пока ZAVOD
   запускает Pi с `--no-extensions` по путям снапшота, поэтому выделение
   `agent-kit-inspection` меняет и релизный конвейер: либо снапшот собирается
   из набора checkout'ов, либо провайдер остаётся в core-снапшоте до перехода
   ZAVOD на ZIP. Действующие процессы и immutability опубликованных снимков не
   нарушаются.
6. **Три машины.** Рабочая (Core+Cloudru+Inspector), личная VM (Core, при
   необходимости +Inspector), чистая машина коллеги (ничего из agent-kit).
   Проверка: `agent-kit status` показывает ожидаемый профиль, в
   `~/.pi/agent/skills` нет рабочих навыков там, где их не должно быть, GitTask
   и субагенты работают в Pi TUI и через ZAVOD, Claude CLI видит `agent-kit
   task`.

Исходный checkout и его ветки не удаляются до доказанной эквивалентности
запуска и корректного владения ссылками.

## 4. Критерии готовности к выделению

`agent-kit-inspection` → отдельный репозиторий:

- контракт и версия capabilities зафиксированы
  (`extensions/inspection-provider/README.md`), ZIP-транспорт и wire — на
  стороне контроллера (`docs/adr/adr-0006.md`,
  `extensions/inspection-provider/README.md`);
- провайдер не регистрирует инструменты, промпты, команды и статусы и инертен
  без bridge-реестра — заявлено в
  [`extensions/inspection-provider/README.md`](../extensions/inspection-provider/README.md)
  и покрыто тестами расширения;
- Core читается только через версионированный seam; несовместимая версия или
  отсутствие источника отключают только соответствующие capabilities, остальные
  продолжают работать;
- снапшот с провайдером проходит проверку схемы 2 (`tests/snapshot/run.sh`, T25);
- **остаётся**: релиз ZAVOD, который говорит по ZIP и не требует устаревший
  FD-канал; решение владельца о площадке и публикации. До этого
  `extensions/inspection-channel/` (deprecated-носитель) и
  `extensions/inspection-provider/` живут в одном checkout'е.

`agent-kit-core` → собственный репозиторий: полный прогон тестов зелёный,
`agent-kit task` и форматы `links*.tsv`/`hosts`/`command.tsv` не меняются,
Core не ищет ZAVOD ни по env, ни по путям.

`agent-kit-cloudru` → отдельный (не публичный) репозиторий: `WORK_SKILLS`
совпадает с содержимым его `skills/`, установка идёт поверх Core
(`agent-kit install --profile full` в текущем репозитории — временный механизм),
внутреннее содержимое навыков не попадает в публичную спецификацию и отчёты.

## 5. Откат

- Ссылки: `bin/agent-kit` из предыдущего checkout'а или commit'а; форматы
  state не менялись, обе реализации читают одни файлы.
- Профиль: `agent-kit install --profile full` возвращает рабочий навык,
  `uninstall` + `install` — чистое состояние.
- Снапшоты: релизный каталог не переписывается; `current` указывает на
  опубликованный снимок схемы 2, старые снимки остаются валидными до prune.

## 6. Не входит в эту фазу

Создание репозиториев, публикация, перенос истории, изменение имён команд,
переписывание снапшота под несколько checkout'ов, вынос
`skills/kuber-nagibator/` из дерева.
