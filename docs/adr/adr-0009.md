# ADR-0009: выбор host'ов при установке

Status: Accepted
Date: 2026-10-13
Частично заменяет: ADR-0007, решение 1 (выбор host'ов)

## Context

ADR-0007 зафиксировал, что `install` / `uninstall` / `status` всегда работают со всеми hosts сразу. Не на каждой машине нужны все hosts: где-то нужен только Claude Code, где-то только Pi. Установка всех hosts без выбора создаёт на такой машине ссылки, которые никто не использует, а удалить их штатно можно только вместе с остальными.

Существующие установки уже владеют ссылками в обоих hosts, и после обновления инсталлера они должны продолжить работать без ручных действий.

## Decision

1. `install` и `uninstall` принимают необязательные имена hosts (`pi`, `claude-code`):

   ```
   agent-kit install claude-code   # только Claude Code
   agent-kit install pi            # добавить Pi к выбору
   agent-kit install               # reconcile выбранных hosts (по умолчанию — всех)
   agent-kit update                # pull --ff-only + reconcile выбранных hosts
   agent-kit uninstall pi          # снять ссылки одного host и убрать его из выбора
   agent-kit uninstall             # снять ссылки всех hosts и очистить выбор
   ```

   Неизвестное имя — ошибка с кодом 2 до любых изменений.
2. Выбор хранится в `$XDG_STATE_HOME/agent-kit/hosts` (по умолчанию `~/.local/state/agent-kit/hosts`), по одному host на строку, рядом с `links*.tsv` и `command.tsv`. Запись атомарная (временный файл + `mv`). Строки с неизвестными именами игнорируются с предупреждением.
3. Записанный выбор — содержимое этого файла. Если файла нет (установка сделана до этого решения), выбор выводится из link state: выбраны hosts, чей state-файл (`links.tsv` для `pi`, `links-claude-code.tsv`) содержит хотя бы одну валидную строку. Поэтому существующая установка в оба host сохраняет оба.
4. `install` без аргументов работает с записанным выбором; `install <host>...` — с объединением записанного выбора и аргументов. Пустой выбор означает «ничего не выбрано» и трактуется как свежая машина: голый `install` ставит все hosts. Это относится и к выбору, опустошённому через `uninstall <host>...`. Reconcile идёт только по выбранным hosts; ссылки невыбранных hosts `install` и `update` не трогают. После reconcile выбор записывается в файл.
5. `update` запускает голый `install` свежего инсталлера и поэтому сохраняет выбор.
6. `uninstall <host>...` снимает ссылки только этих hosts и убирает их из выбора; файл остаётся, даже пустой. `uninstall` без аргументов снимает ссылки всех hosts и удаляет файл выбора.
7. `status` показывает выбор и его источник (записан в файле / выведен из существующих ссылок / по умолчанию все) и, как раньше, состояние каждого host; невыбранные помечаются `not selected`.
8. Миграция legacy state и bootstrap лаунчера `~/.local/bin/agent-kit` работают как прежде, независимо от выбора.

## Consequences

- На машине, где нужен один host, ставится `agent-kit install <host>`, и последующие `install` / `update` не создают ссылок второго.
- Установки, сделанные до этого решения, продолжают обслуживать оба host без повторной установки; файл выбора появляется при первом `install` или `update`.
- Явно опустошённый выбор и свежая машина неразличимы: голый `install` после `uninstall` всех hosts по одному ставит все hosts. Чтобы ставить один host, его называют явно.
- Добавление следующего host по-прежнему — ветка в `use_host` и `entities` плюс имя в `HOSTS`; формат файла выбора не меняется.
