# ADR-0005: headless execution на штатном `pi --mode rpc`

Status: Accepted
Date: 2026-09-14

## Context

ADR-0001 (§9) зафиксировал, что headless execution принадлежит agent-kit, но не определил форму интерфейса. ADR-0004 закрыл вопрос восстановления: отдельный durable Run runtime не вводится, восстановление опирается на Pi session + Git/worktree + task artifacts.

A6 проверил живыми экспериментами на Pi 0.85.1, достаточно ли штатного RPC-режима Pi как минимального headless-интерфейса обычной Main-сессии agent-kit, или нужен собственный runtime.

## Verified behavior

Живыми экспериментами подтверждено:

- в `pi --mode rpc` skills, extensions и prompt templates загружаются так же, как в TUI; обычные запросы, `/spec` и `/dev` работают без изменений;
- `ask` деградирует в штатные Extension UI диалоги (`extension_ui_request`/`extension_ui_response`): структурированные вопросы, recommended-подсказки, описания опций, свободный ответ и review step сохраняются; ответ продолжает тот же agent turn; отмена диалога прерывает turn (fail-closed контракт сохранён);
- `subagent` (workspace RepoOwner) работает без изменений: блокирующий dispatch, structured terminal envelope, объективные `git_facts`, отклонение `done` на грязном дереве;
- `abort` прерывает turn Main и отцепляет workspace run: Main сразу свободна, RepoOwner завершает работу, результат доставляется в сессию;
- `SIGKILL` Main и закрытие stdin завершают и RepoOwner; worktree, Git-состояние и task artifacts сохраняются;
- `pi --mode rpc --session <file>` возобновляет ту же сессию; новый RepoOwner продолжает работу по фактическому состоянию worktree (модель ADR-0004 работает под RPC без изменений);
- event stream (turn/tool/message-события) плюс session JSONL и `get_entries` с курсором по `entry id` достаточны для внешнего наблюдения; durable история переживает рестарт;
- `--mode json` и `-p` не подходят: это одноразовые прогоны без канала управления, и `ask` в них fail-closed (подтверждено живьём).

## Decision

Headless execution использует штатный `pi --mode rpc`. Agent-kit не вводит собственный Run runtime, daemon, socket/server, event journal, process registry, RPC-протокол или adapter поверх Pi.

Восстановление остаётся таким же, как в ADR-0004: новая Pi-процесс возобновляет session, состояние разработки восстанавливается из Git/worktree/task artifacts, Main запускает нового RepoOwner.

Управляющий канал для внешнего клиента — команды штатного RPC (`prompt`, `steer`, `abort`, `get_state`, `get_messages`); доставка `ask`/`needs_input` — штатный Extension UI sub-protocol (`extension_ui_request`/`extension_ui_response`). Это reliable control-канал; `agent-events` остаётся telemetry-only (ADR-0001 §8).

Внешний клиент (будущий agent node) запускает процесс Pi, говорит с ним только через этот протокол и не импортирует extension modules (ADR-0001 §6, §10).

## Consequences

### Positive

Headless-режим не требует ни строки production-кода agent-kit. Interactive и headless исполнение — один runtime и один workflow (ADR-0001 §9). Восстановление опирается на уже верифицированные в A5/A6 механики.

### Limitations

- live-события идут best-effort по pipe процесса; durable история — session file и `get_entries`;
- reconnect к живому процессу не поддерживается: после смерти управляющего процесса наблюдение продолжается только через session resume;
- идентификация `ask`-диалогов среди прочих `extension_ui_request` — по форме диалога; семантика остаётся на стороне клиента.

## Rejected alternatives

### Собственный daemon, Run runtime, event journal, process registry

Отклонено: ни одно требование A6 не потребовало нового состояния выполнения. Модель восстановления ADR-0004 закрыла crash-кейс без них; отмену, наблюдение и ответы на вопросы штатный протокол уже обеспечивает.

### `--mode json` или `-p` как headless-канал

Отклонено: одноразовые режимы без stdin-канала команд; `ask` в них fail-closed. Для длительной управляемой сессии непригодны.

### Adapter/wrapper вокруг RPC

Отклонён до появления конкретного gap: старт процесса, JSONL-обмен и ответы на ui-запросы клиент решает напрямую; обобщать нечего.
