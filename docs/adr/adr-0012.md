# ADR-0012: инсталлер agent-kit на Node.js

Status: Accepted
Date: 2026-10-31

## Context

`bin/agent-kit` вырос до ~1 800 строк Bash и совмещал всё: разрешение checkout'а,
описание желаемых ссылок, ownership-state, legacy-миграции, выбор host'ов,
bootstrap лаунчера, `update`, запуск `task` через Bun и снимки для headless-хостов.
Bash-реализация содержала отдельные ветки под BSD/GNU userland, а модели владения
(чужая ссылка, перенаправленная своим владельцем, реальный файл, порченый state)
проверялись только через сквозные shell-тесты с настоящей файловой системой.

Node.js уже требуется окружению ZAVOD (>= 24), а на машинах с Pi и Claude Code он
присутствует по факту. Bun остаётся runtime для task-workspace и hooks: у него нет
причин меняться.

## Decision

1. `bin/agent-kit` — Node-скрипт (ESM, shebang `#!/usr/bin/env node`), требующий
   Node.js >= 24. Он работает сразу после `git clone`: без `npm install`, сборки,
   сети и без `node_modules` — только `node:` builtins и относительные модули.
2. Модули разделены по владению, без CLI-фреймворка: `lib/paths.mjs` (расположение
   checkout'а, корни host'ов, state-каталог, предикаты путей), `lib/entities.mjs`
   (какие ссылки хочет репозиторий), `lib/state.mjs` (записанное владение, выбор
   host'ов, запись лаунчера), `lib/legacy-state.mjs` (единственное место, где
   называются вышедшие из употребления runtime'ы), `lib/reconcile.mjs` (сверка
   state с реальной файловой системой), `lib/update.mjs` (git и запуск свежего
   инсталлера), `lib/task.mjs` (передача в Bun). `bin/agent-kit` — только диспетчер:
   валидация аргументов, таблица команд, коды завершения.
3. Публичный контракт не меняется: имена команд, аргументы, коды завершения,
   формат `$XDG_STATE_HOME/agent-kit/{links.tsv,links-<host>.tsv,command.tsv,hosts}`
   и смысл ownership-правил те же. Формат state — «одна строка на ссылку»; пустые
   строки при чтении игнорируются, поэтому файлы, записанные прежней реализацией
   (с завершающей пустой строкой), читаются без миграции, а новая запись этой
   строки не добавляет. Строка, которую нельзя прочитать обратно как ровно тот
   путь, который она называет (сегмент `.`, пустой сегмент, управляющий символ),
   отбрасывается при чтении, а сущность с таким именем не устанавливается: запись
   о владении не может расширить набор путей, которые разрешено удалять.
4. `snapshot` остаётся в Bash на время: `bin/agent-kit-snapshot` — временный,
   явный мост, которому диспетчер делегирует ровно эту команду. Мост удаляется
   вместе с делегированием, когда снимки переезжают отдельной задачей; новых
   поведений в нём не появляется.
5. `update` по-прежнему `git pull --ff-only`, затем запускает **новый** файл
   `$REPO/bin/agent-kit install` отдельным процессом: код, загруженный до pull,
   устарел и не должен сверять ссылки.
6. Откат: checkout предыдущего коммита (или прежнего checkout'а) содержит
   Bash-инсталлер, который читает и пишет те же state-файлы и те же симлинки.
   Форматы совместимы в обе стороны, поэтому откат — это запуск прежнего
   `bin/agent-kit`, без миграции состояния.

## Consequences

- Для `install`, `uninstall`, `status`, `update`, `help` и `task` нужен Node.js
  >= 24; для `snapshot` до его переноса — ещё и Bash.
- Платформенные различия сводятся к `fs.realpath`/`lstat` вместо разных
  `readlink`/`stat`-веток; замена ссылки при relink и запись state — rename, а не
  unlink+create.
- Сквозные shell-тесты остаются владельцами контракта: они запускают настоящий
  исполняемый файл в песочнице `$HOME`, поэтому не зависят от внутренней
  раскладки модулей.
- Появляется требование к хостам, где раньше хватало Bash. Без Node не работают
  ни `install`/`update`/`status`, ни `task`-обёртка: лаунчер плагина Claude Code
  (`bin/agent-kit` плагина) делает `exec` в `bin/agent-kit` checkout'а, поэтому
  цепочка hooks завершается ошибкой запуска. Fail-open покрывает только
  отсутствие Bun, когда Node есть.
