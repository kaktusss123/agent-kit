# ADR-0007: один checkout устанавливается в несколько hosts (Pi + Claude Code)

Status: Accepted
Date: 2026-10-12
Частично заменяет: ADR-0001, раздел 2 («Pi является текущим runtime») в части инсталлера
Частично заменён: ADR-0008 (task-workspace runtime в Claude Code; пункт Consequences об отсутствии в Claude Code runtime, `git-task` и `git-commit` устарел), ADR-0009 (выбор host'ов, решение 1)

## Context

ADR-0001 запретил multi-harness слои до появления второго реального consumer. Он появился: Claude Code используется параллельно с Pi, в будущем вероятен OpenCode. Отдельный downstream-проект означал бы вторую копию skills и правил, которую нужно синхронизировать вручную.

Большая часть ценности agent-kit — skills и `rules/AGENTS.md` — по формату уже совместима с Claude Code (Agent Skills, `SKILL.md` + frontmatter). Pi-специфичны extensions, prompts и skills, опирающиеся на task-workspace runtime (`git-task`, `git-commit`).

Конфигурация host не должна ссылаться на расположение checkout'а или на каталог другого host: на другой машине этих путей может не быть. Единственные пути, на которые можно опираться, — те, что инсталлер сам создаёт внутри корня host.

## Decision

1. `agent-kit install` / `uninstall` / `status` всегда работают со всеми hosts сразу: `pi` (`$PI_AGENT_DIR`, по умолчанию `~/.pi/agent`) и `claude-code` (`$CLAUDE_CONFIG_DIR`, по умолчанию `~/.claude`). Аргументов выбора host нет, autodetection нет.
2. Раскладка репозитория остаётся desired state. Для `claude-code`:
   - `skills/*` → `skills/*`;
   - `rules/AGENTS.md` → `rules/agent-kit.md`;
   - `rules/claude-code.md` → `rules/agent-kit-claude-code.md` — короткий mapping Pi-терминов на Claude Code.

   Файлы в `~/.claude/rules/` загружаются Claude Code автоматически, поэтому `~/.claude/CLAUDE.md` не содержит импортов agent-kit и остаётся под личные инструкции.
3. Skill ограничивает свои hosts полем `metadata.hosts` (список через запятую) во frontmatter `SKILL.md`. Без поля skill ставится во все hosts. `metadata` — штатное поле Agent Skills; Pi и Claude Code его игнорируют.
4. Ownership-модель прежняя, state — отдельный файл на host: `links.tsv` для `pi` (совместимо с существующими установками), `links-<host>.tsv` для остальных. Существующая ссылка, уже указывающая ровно на источник, принимается во владение; всё остальное — conflict.
5. Слои `shared/`, `runtimes/`, `bindings/` по-прежнему не вводятся. Host-различия живут в инсталлере (таблица entities на host) и в host-специфичных файлах там, где различие реально есть.

## Consequences

- Один `git pull` + `agent-kit install` обновляет оба host.
- В Claude Code пока нет task-workspace runtime: guard, managed worktrees и RepoOwner недоступны, `git-task` и `git-commit` не ставятся. Перенос — отдельное решение (CLI + hooks плагина, без MCP из-за корпоративной политики).
- `prompts/` пока ставятся только в Pi.
- Добавление следующего host — новая ветка в `use_host` и `entities` плюс тесты; формат state не меняется.
