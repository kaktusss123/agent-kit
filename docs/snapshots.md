# Снимки для запуска без TUI

## Подготовка и запуск

`agent-kit snapshot <releases-dir>` закрепляет набор расширений и зависимостей
Pi и переключает на него стабильный указатель. Это необязательный шаг установки;
снимок не содержит внешнюю инспекцию или отдельный управляющий сервис.
Нужны Node.js >= 24, `git` и пакеты Pi в `node_modules/` checkout.
[Подготовка зависимостей](../CONTRIBUTING.md) описана отдельно.

```sh
agent-kit snapshot ~/.local/share/agent-kit-releases
```

Checkout должен иметь HEAD и быть чистым: изменённые и неигнорируемые новые
файлы вызывают отказ с кодом 2 и перечнем путей. Проверки выполняются под
блокировкой каталога выпусков и повторяются перед копированием.
Состав `extensions/` задаёт `git ls-files --cached`, не обход каталога.

Файлы читаются из рабочего дерева, не из объектов Git. Пока команда копирует,
никто не должен менять checkout или его зависимости. Блокировка каталога
выпусков не запрещает запись в исходный checkout другим процессом.
Игнорируемые файлы расширений, которых нет в коммите, в снимок не попадают.

## Результат

Каталог `<releases-dir>/<full HEAD sha>/` содержит `extensions/`,
`node_modules/` и `manifest.json`. Манифест имеет ровно пять полей:

| Поле | Значение |
| --- | --- |
| `schema` | `2` |
| `sha` | Полный SHA коммита |
| `dirty` | `false` |
| `createdAt` | Время создания в UTC, строка ISO 8601 |
| `source` | Путь исходного checkout |

Расширения копируются с сохранением симлинков и Git-режимов файлов.
`node_modules` копируется из checkout либо хардлинкуется из проверенного
снимка текущего формата. С исходным checkout общих inode нет.
**Не редактируйте опубликованные снимки:** правка общего inode изменит
зависимости сразу в нескольких снимках.

Сборка идёт во временном каталоге, затем публикуется переименованием.
`current` является относительным симлинком на полный SHA и переключается
атомарно на проверенный полный снимок. Повторный запуск для того же HEAD
проверяет и переиспользует каталог, исправляет `current`, если нужно,
и применяет хранение: сохраняются цель `current` и пять новейших снимков.

## Блокировки и отказы

Все операции над одним `<releases-dir>` сериализует `.lock`, симлинк с записью
владельца. По умолчанию ожидание ограничено 60 секундами;
`AGENT_KIT_SNAPSHOT_LOCK_TIMEOUT` задаёт предел в секундах.
Перехват разрешён только для доказуемо мёртвого процесса на том же хосте.
Возраст записи не даёт права перехвата. Живой владелец, другой хост,
нечитаемая запись или переиспользованный PID приводят к ограниченному отказу,
если блокировку не удалось получить. Не удаляйте блокировку живого процесса.

Артефакт с неполным набором обязательных файлов или неподходящим манифестом
не переиспользуется. Проверка не сверяет всё содержимое с объектами Git.
При отказе из-за существующего каталога SHA проверьте диагностируемый путь,
убедитесь, что его никто не использует, уберите его из каталога выпусков
и повторите команду. Не исправляйте манифест вручную ради прохождения проверки.
Ошибка сборки не переключает `current` на недособранный каталог.

После прерывания следующий запуск под блокировкой убирает временные каталоги,
временные ссылки `current` и блокировку доказуемо мёртвого владельца.
Перед удалением каталоги переименовываются в зарезервированные trash-имена.
Неудачное удаление вызывает предупреждение, не отменяет успешную публикацию;
остаток попробует удалить следующий запуск.

Проверка владения и переименование не составляют единую атомарную операцию.
При конкурентной подмене путей остаются окна гонки, в том числе при удалении
кандидата, ставшего `current`. Используйте один писатель и не меняйте вручную
каталог выпусков во время команды. Потеря блокировки останавливает писателя
на ближайшей проверке, но не превращает файловую систему в транзакционную.
